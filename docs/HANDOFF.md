## Delivered behavior and integration

[LICENSING_AND_SETTINGS.md](LICENSING_AND_SETTINGS.md) records the full runtime contract, capability catalog additions, route list, D31 defaults, migration implications, fixtures, two real bugs found and fixed during this phase's own testing, and detailed evidence. Phase 04's organization/policy contract is unchanged; `loadPolicy` (apps/api/src/modules/organization/policy.ts) now additionally computes and enforces `licenseStatus`.

New capabilities: `licensing.manage`, `seats.release`, `branding.manage` (reserved, SYSTEM-only); `modules.manage`, `users.manage_staff`, `users.create_parent`, `parents.block` (delegable). Seat reservation is a real Postgres row lock on `license_limits` plus a partial-unique-indexed `seat_reservations` ledger, not a coarse advisory lock — the A04 race test exercises this directly. Only `seats.release` ends or restores a reservation; ordinary deactivate/reactivate/block/unblock explicitly refuse a `RELEASED` account (`licensing.useRestoreAction`) so a delegated admin can never bypass the seat ledger. `loadPolicy` blocks every non-SYSTEM request once the license is `SUSPENDED` (Cairo-date grace/valid_until boundary via `subscriptionAccessStatus` in `packages/domain`); SYSTEM is never blocked. Module settings have no branch column (identical by construction); re-enabling FINANCE after a disable requires a preview + `catchupAcknowledged: true`, which today always reports zero missing periods pending Phase 14's billing engine (an honest stub, documented as the integration point). Nursery branding/theme is SYSTEM-only and contrast-validated with the same WCAG helper on server and client.

Two real defects were found and fixed while writing this phase's own tests (not shipped): provisioned accounts were missing `temporary_expires_at` (so they could never actually log in), and `reactivateAccount`/`unblockAccount` did not reject a `RELEASED` target (a real seat-bypass gap). A third issue was found and fixed in the web layer: `BrandingProvider` sharing the authenticated app's `AuthClient` instance caused an intermittent hang in heavier e2e interaction tests; it now uses its own independent client (see LICENSING_AND_SETTINGS.md's verification section for what was and wasn't conclusively isolated about the mechanism).
