# Parent hub and communication — Phase 12 execution

Status: IN PROGRESS. The final acceptance gate is pending; do not infer completion from this implementation record.

## Contracts and ownership

`communication.ts` defines strict announcement targets (nursery, branch, classroom, selected parents, selected children), bounded plain text, optional acknowledgment and inclusive holiday dates. `announcements.manage` is delegable capability data; migration 0010 grants no role permissions. Nursery targeting is SYSTEM-only; branch targeting requires branch scope. Selected-parent publication requires authority over every active linked child and locks selected accounts through the existing sorted account-lock protocol. Child targets use current child authority. Recipient witnesses are snapshotted at publication and never returned to parents.

API: `POST /api/v1/announcements`, `GET /announcements/options`; guardian-only `/parent/announcements`, `/parent/announcements/:id`, `POST /parent/announcements/:id/acknowledgment`, `/parent/notifications`, `PUT /parent/notifications/:id/read`, `/parent/contact`, `/parent/live`. Existing cookie, CSRF, no-store and SafeError hooks apply. Query pages are bounded to 50, default 20. Published notices and recipient witnesses are immutable; acknowledgments are unique per notice/guardian and repeat safely. Notice reads revalidate active child, current read link and the original branch/classroom target. Selected-parent/child/nursery targets still require an original recipient witness. New links never become implicit recipients of old notices.

Migration `0010_communication.sql` adds announcements, private recipient witnesses, immutable acknowledgments, append-only planned-absence communication events, a durable per-guardian read-state inbox and a view over immutable upstream sources. Source rows/outboxes are never marked delivered or modified. Inbox uniqueness is `(event_key, guardian_id)`. One notice has one notification per guardian even with several sibling witnesses; reads choose a currently authorized witness. Delivery is recipient-local on snapshots/live ticks, bounded to 200 candidates per transaction, retries use `ON CONFLICT`. Disabled/lost-link items are excluded from pages and counts; stored read state survives re-enable. Source identities and inbox read state form the delivery boundary for later financial/event adapters, which must add their real module/permission checks; no financial producer is implemented here.

## Producers and payload policy

Sources: `learning_change_outbox`, `homework_content_outbox`, incident `notification_events`, `attendance_absence_alerts`, new planned-absence changed-submission events, announcements/holiday notices. Unexpected absence replaces the generic learning notification for the same attendance event. Homework content and learning outcome identities remain separate. Identical planned-absence resubmissions stage no additional event; the submitting guardian gets a confirmation if its current notify/read flags permit it. Existing teacher roster advisories remain authoritative.

Parent notification DTOs contain only notification ID, kind, currently permitted witness child ID, business date, read flag and a generated local deep link. No incident description, health information, instructions, recipient IDs, audit timestamps or internal reasons are broadcast/stored in a notification payload. Targets are fetched again through scoped services; guessed or newly inaccessible IDs fail generically.

The actual Phase 09 implementation has no calendar/holiday store. The narrow prerequisite addition here is an immutable, dated holiday announcement using the same target/acknowledgment/notification rules. It never marks attendance or infers No class day. A full working-week/calendar editor is not implemented as a side effect.

## Live delivery and parent UI

SSE `/parent/live` accepts an optional currently readable child ID. Each one-second tick opens a short `ChildService.withPolicy` transaction, revalidating session/account/license and locking current link/child witnesses. It compares private signatures of current access, permitted source identities, read/acknowledgment state and modules. Wire events `snapshot`, `invalidate`, `revoked`, `reconnect` contain `{}` only. Heartbeat comments occur every ten successful ticks. Scope/link/placement loss or failed policy validation sends a neutral revocation then closes. Streams are limited to three per account per API process and reconnect after 15 minutes. There is no record replay based on Last-Event-ID; reconnect triggers authoritative snapshot reads. Revocation detection is bounded by the next tick plus database/network latency; every ordinary request checks current authorization immediately.

`ParentLive` uses native EventSource in production and fresh scoped reads on connect/reconnect/invalidation/focus. Errors reconnect with 1–10 second bounded backoff; the existing five-second foreground polling remains the fallback. Hidden pages close subscriptions and drop child queries before revalidation. Logout/unmount closes the stream. Shared `useScoped` queues an invalidation during an in-flight read and discards its obsolete response; records are tagged by path to prevent child-switch flashes. No sensitive browser persistence or PWA cache is added.

Parent home redirects to Today with a compact permitted active-child selector, existing daily bar/status cards, date-filtered exam/homework detail, grouped dated history, profile and enabled health/pickup links. Paused children show neutral contact cards. The five labeled destinations wrap on narrow screens; parent body copy uses 18px. Stable profiles retain existing attendance/planned-absence/safety components. Nursery contact uses server-normalized WhatsApp numbers and a user-clicked external `wa.me` link; no message API/send occurs.
