## Required input and onboarding

POST /api/v1/children/onboarding takes operationId UUID, 1–4 guardian entries and 1–10 child entries, bounded to 64 KiB JSON. NEW guardian requires normalized username and profile {fullName,mobile}; EXISTING takes accountId, optional profile only when SYSTEM initializes an unattached Phase 05 parent. Each child takes {code,fullName,birthDate,branchId,classroomId,contacts}; birth date cannot be future, classroom nullable, contacts up to 10 {fullName,mobile,relationship}. Every guardian must be used by at least one child; each child has at least one distinct guardian-index link with relationship and booleans read/finance/pickup/notify (defaults true/false/false/true). Shared account identity does not imply access to another child.

Capabilities children.manage and guardians.manage are mandatory; NEW parents also require users.create_parent. All placements and existing parents are rechecked under current policy. New parent accounts, temporary credential hashes/expiry, reservations, profiles, children, contacts, links, initial lifecycle/classroom history, audit and operation record commit together. Quota failure or audit failure rolls all back. Existing parents reserve no additional seat. No fee ledger is fabricated. Actor-account locking serializes same-operation retry; input hash mismatch is IDEMPOTENCY_CONFLICT. Replay revalidates child scope and returns child/guardian IDs, no original passwords. Fresh 201 response returns initial passwords once; replay is 200. UI keeps credentials in memory and clears on dismissal, blur/visibility/navigation; no browser record/password persistence. A configured non-suspended license is required for new onboarding.

## Resource policy and lifecycle

Staff data requires capability and assigned branch/classroom intersection; custom role names never drive decisions. Guardian read requires live account/session/license, own active link with can_read, ACTIVE child. Parent lists expose PAUSED name/contact-message cards only; ARCHIVED omitted. Finance/pickup/notify permission checks use the same link helper for future services. Missing or unauthorized child/file IDs fail closed. Staff duplicate conflicts remain generic. Profile edits affect all linked children and require authority over all of them; block/unblock require authority over every active linked child (unattached accounts SYSTEM-only). Block one guardian without changing another guardian or sibling's access.

PUT /children/:id updates name/birth date/contacts with expectedVersion. POST /children/:id/lifecycle takes expectedVersion/status/reason/publicMessage. ACTIVE ↔ PAUSED, either may ARCHIVE, no restore from archive. Effective date is current Cairo date; history is database-enforced append-only. Archive durably emits child.archived with END_FUTURE_MONTHLY_GENERATION for Phase 14; Phase 14 must consume authoritative lifecycle state/effective date before generation, without voiding issued charges. Pausing never changes fee agreements; Phase 15 collections/manual blocking remain separate. No actual financial mutation exists here. POST /children/:id/classroom-moves takes expectedVersion/classroomId/reason, accepts same-branch authorized classroom or unassigned, retains history. SQL rejects branch changes pending Phase 17. Capacity warnings use ACTIVE occupancy and are advisory snapshots; no admission quota is implied. Unassigned/paused/archived children fail activeClassroomChild for future daily rosters.

PUT /children/:id/guardian-links takes expectedChildVersion/accountId/relationship/permissions/active and advances child/link versions; PUT /guardians/:id updates profile with expectedVersion. GET /children/options supplies scoped placements/capabilities and integration: finance {enabled,implemented:false}, transport {implemented:false}, availableSteps accounts/children/documents. No unimplemented finance/transport form is shown. Search uses literal bounded substrings, limit <=100 and offset <=100000, a single consistent query for count/items.

## Private documents and cleanup

POST /children/:id/documents takes name, nullable expiresOn, mimeType, contentBase64; maximum decoded 5 MiB and JSON request ~7 MiB. PDF 1.0–1.7 with EOF is actually parsed (unencrypted, 1–100 pages); action/interactive/embedded-file structures are rejected recursively. JPEG/PNG are fully decoded and re-encoded, max 16 million pixels, one page, metadata/trailing bytes removed. Re-serialized output must also fit 5 MiB. This is validation, not an antivirus claim; interactive PDFs are intentionally unsupported.

Storage is PRIVATE_FILES_DIR/child-documents, generated UUID.blob only, exclusive creation and restrictive modes, no caller paths. Root symlinks/web application paths rejected; downloads check regular-file integrity hash and size. GET /child-documents/:id/download checks current documents.manage plus child scope and returns attachment with generated safe filename; administrative documents are never exposed to guardians. Metadata lists omit physical storage paths. POST /child-documents/:id/retire {} removes availability while retaining referenced bytes and audit. Expiry is administrative metadata, no automatic deletion/blocking.

File/metadata/audit upload runs under policy/child/file locks; failure checks persistent references before removing its private candidate, avoiding deletion after uncertain successful commit. If DB reconciliation is unavailable, leave a private orphan for conservative cleanup. POST /child-documents/cleanup {} requires reserved support.access (SYSTEM), exclusive file lock, deletes only generated unreferenced blobs older than 24 hours; ignores symlinks, recent/retired-referenced/unrelated files. No public storage or arbitrary deletion API exists.
